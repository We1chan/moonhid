# Xbox 蓝牙手柄实测

2026-10-07，参赛者在 Windows 的 Chrome 中选择已通过蓝牙连接的 Xbox 手柄，
按下、松开 A，并将左摇杆移到两端后回中。WebHID 收到 42 条 Input，Report ID 为 0，
每条载荷 15 字节。浏览器未提供产品名；VID/PID 为 `045e:0b13`，具体硬件修订及固件未知。
型号和连接方式由参赛者说明，未额外核验产品序列号。

| 实际报告序号 | 观测 |
| --- | --- |
| 1 / 2 | Button Usage 1 从 1 变为 0，与 A 按下、松开的操作对应 |
| 6 / 16 | X 原始值分别为 0 / 65535 |
| 40–42 | 五个 16 位轴均为 32768，16 个按钮均为 0 |

这是操作系统提供的报告载荷，不是蓝牙空中报文。字段位布局为五个 16 位轴
（X/Y/Rx/Ry/Z）、16 个一位按钮、四位 Hat 和 20 位填充。
原始设备描述符没有取得，不能凭此声称完整协议兼容、物理范围正确或所有按钮都经过测试。

## 实测发现与修正

最初采集页将浏览器的轴逻辑上限 `-1` 写成一个字节 `ff`。
在非负下限下，MoonHID 按 HID 规则将其解释为 255，实际中位值 32768 被标为越界。
采集器现在拒绝不完整的逻辑范围，提示提供原始描述符或明确选择「按位宽查看原始值」。
该模式使用可表示的位范围，忽略原始 Logical、Array 与 Null 语义，并在导出记录中标记限制。
它只能验证原始位值的变化。

[回归数据](../examples/device-cases/xbox-bluetooth.json) 保留全部 42 条原始十六进制报告、
独立按位读取的预期值、原始导出文件 SHA-256，以及最初参考描述符和对照差异。
当前参考描述符由作者根据观测位布局编写，轴范围显式采用 0–65535，按钮采用 0–1；
Hat 仅作为四位原始数值读取。它不冒充设备原始描述符。
